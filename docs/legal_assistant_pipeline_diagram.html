LegalAssistant  ·  build_knowledge_base.py

From bare acts to a queryable knowledge base

Five stages, one script. Ends at chroma_db_legal_bot_part1/
01five stages
Raw statute text

Bare-act PDFs — the Constitution, BNS, BNSS, BSA, Consumer Protection Act, and others — are sourced from an official repository like India Code, then read page by page to pull out their raw text.

data/raw_pdfs/*.pdf → pdfplumber.extract_text() → raw text (in memory)
Typical raw outputTHE GAZETTE OF INDIA EXTRAORDINARY Section 1. Short title and commencement. This Act may be called the Test Act, 2024. It shall come into force on such date as the Central Government may notify. 1
02
Cleaning

The raw text is normalized: repeated headers like "THE GAZETTE OF INDIA", stray page numbers, and broken line-wraps from the PDF layout are removed or rejoined, so each section reads as one continuous, well-formed passage.

strip page numbers & headers → rejoin wrapped lines
After cleaningSection 1. Short title and commencement. This Act may be called the Test Act, 2024. It shall come into force on such date as the Central Government may notify.
03
Chunking

Cleaned text is split on real Section N / Article N boundaries — not arbitrary character counts — so each chunk is one legally coherent unit. Every chunk keeps its source act and section number as metadata.

regex: Section/Article boundaries → chunk + {source, section}
One chunk, tagged{ "text": "Section 3. Punishment for theft. Whoever commits theft shall be punished with imprisonment...", "metadata": { "source": "bns_2023", "section": "Section 3" } }
04
Embedding

Each chunk's text is passed through OpenAI's embedding model, which converts it into a vector — a list of numbers capturing its meaning, so that "theft" and "stealing" land close together even though they're different words.

chunk text → OpenAIEmbeddings() → [0.014, -0.22, 0.19, ...]
05
Persisting to disk

Every vector, alongside its original chunk text and metadata, is written to a persistent Chroma vector store. This single folder becomes the finished, queryable knowledge base the whole application runs on.

Chroma.from_documents(persist_directory=...) → chroma_db_legal_bot_part1/
The finished artifact

chroma_db_legal_bot_part1/

A SQLite database plus a vector index (HNSW), on disk. Every legal question the app receives is matched against this store first — this is the entire knowledge base the assistant can draw on, and nothing else.

chroma.sqlite3 — text + metadata
data_level0.bin — vector index
header.bin — index config
link_lists.bin — HNSW graph links
build_knowledge_base.py  ·  run once per data update, not per query
